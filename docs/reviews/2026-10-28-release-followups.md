# v0.29.0 后续审查修复 — 2026-10-28

基线为 `a575b1c`。本轮按 worth-fix 复核上一轮报告，修复两个已复现的行为

## 证据与取舍

- **坐实：拒绝未完成提案被误拦，中等优先级。** 新增命令测试填写问题、
  方案、备选，但让验收条件与风险保持注释。旧代码的 `rejectCommand`
  报这两节缺正文，无法拒绝；`validate` 与 `implement` 失败则符合预期。
  这是普通否决流程的回归，局部修复成本低，应修。现在先确认源仍是提案，
  再按否决记录要求检查源的结构与元数据；已有笔记保留，未写备选仍失败。
- **坐实：相同内容的并发归档仍可能丢失唯一副本，中等优先级。**
  `test/review-regressions.test.ts` 在 A 删除源的边界注入 B 的真实
  `retireRecord` 调用及 A 的删除错误。两次使用同一理由、同一日期。旧代码
  允许 B 覆盖同名归档并删除源，随后 A 的字节比较仍相等，回滚删掉 B 的
  唯一归档；修复前测试在“源仍存在”断言失败。需要并发与删除异常，概率
  较低，但后果是记录丢失，值得修。修复在 `writeRecord` 拒绝覆盖已有归档，
  并以 `wx` 独占创建作为写入保证；B 无法接管 A 的目标，A 失败后仍保留源，
  重试可完成归档。直接写入测试同时覆盖相同字节与不同字节的覆盖尝试。
- **坐实：升级说明不完整。** 收紧空 `Consequences`、`Acceptance criteria`、
  `Risks` 的校验会让旧记录失败，原 changeset 与 CLI 参考不足以替代升级
  指引。补齐双语 README、格式参考、模板提示和本仓库常设指令。缺失的真实
  后果或验收依据不能机械生成，须由作者补写，不用占位内容蒙混过关。

## 保证边界与验证

归档修复阻止正常 CLI 移动覆盖另一移动暂存或完成的目标，不依赖“字节相等
就是自己的文件”。无需增加完整生命周期锁或重构。保留的回滚内容比较只是
额外保护已发生的手工修改；不承诺防止任意外部进程替换文件的竞态，也不
提供进程突然退出时的事务恢复（与 ADR 16 的本地恶意竞态边界一致）。

复现使用临时仓库和真实生产函数；删除故障与交错调度由测试注入，并非声称
操作系统自然产生了一次权限故障。两个缺陷的回归测试均先在旧实现失败，
再在修复后通过。可重跑 `npm test`、`npm run typecheck`、`npm run build`
及 `node bin/adrkit.js validate --all`。归档覆盖测试也保留了正常移动与失败
后重试的断言。未更改或迁移任何归档记录正文。
