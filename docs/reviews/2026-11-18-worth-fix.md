## 修复与证据

### 1. resolveProposed 补损坏容错（repository.ts）

- 根因：三个 resolver 共享 `listRecordsForResolve` 的契约（"健康的记录仍可解析"），
  resolveProposed 是未随迁的拷贝。
- 边界：implement 在解析后仍会因完整清单需求拒绝（编号分配的 max 来自可解析记录，
  best-effort 跳过损坏记录可能把已占用编号再分配——writeNumberedRecordLocked 的
  文件名碰撞扫描会拒绝，但 re-run 永远拿到同一个号，死循环）。拒绝并报出损坏文件
  名是唯一健全行为，红测试钉住该契约。
- 红测试：`corrupt-tree resolution` 两例（review-regressions.test.ts）。

### 2. help/version/supersede 空参（cli.ts）

- help/version 加 noPositionals；supersede 的 `--by` 空白值与缺失同报
  `supersede requires --by <name>`（对齐 requireReason）。
- 测试：cli.test.ts 扩展 arity 表 + 空 --by it.each。

### 3. validate 规则覆盖（validate.test.ts）

- 新 describe `rule coverage pins` 12 例：编号提案标题、提案文件名形状、
  文件名日历日期、archived 缺 archived/archive-reason、archived 假日、
  archived 先于 created、archived 元数据越界、文件号≠标题号、status 与目录
  不一致（用 implemented——rejected 在解析层先被拒）、空 paths 条目、缺
  config.yaml（直测 validateRepository：命令层 requireRoot 先行拦截并给修复
  建议）、命令级 duplicate section。

### 4. 技能文本去内部编号（tool-integrations.ts）

- 与 2026-11-17 #3 同类：`(ADR 3, chapter 2, QUESTION 1)` 随
  adrkit-visualize SKILL.md 进入用户仓库，指向不存在或无关的记录。删去括号
  出处，规则句自足。`npm run build` 重建导出，integrations 测试证明无漂移。

### 5. TerminalDemo 修正 + 护栏（site + test/site-transcript.test.ts）

- propose 提示行 `<human|agent>` 占位符形式修正。
- 护栏：解析组件源码提取转录，逐行断言 out/ok 行是真实 record/propose/
  implement 输出的子串（脚本化填写提案后晋升）。站点宣称
  "verified line-by-line" 从此有执行护栏，输出改动会打红。

### 6. adr.test.ts 清理

- 收集 tmp 目录，afterAll 统一删除，与全库其余测试文件对齐。
