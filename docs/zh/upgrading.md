# 升级

ADR Kit 尚未稳定，且有意破坏：版本可能变更记录格式或命令面，不承诺前向兼容。立场见 [README](../../README.zh.md#稳定性)，本页承载逐版本的升级说明；全部变更（含非破坏性）见[更新日志](../../CHANGELOG.md)。

## 受支持的升级路径

1. `npm install -g adr-kit` —— 安装最新版本。
2. `adrkit update` —— 刷新已安装的 agent 集成。
3. `adrkit validate --all` —— 在每个仓库运行；校验错误会指出变化所在。

常设指令会让 agent 升级包、在变更可机械迁移时迁移未归档记录，并如实报告无法迁移的记录而不是硬改。永远不要假设迁移方案必然存在。归档记录只通过有意且说明原因的提交修改。

## 升级说明

按版本从新到旧排列，每条说明变化内容与需要做的事。

### 0.30.0 之后

`paths` 条目不再接受尾斜杠。`src/` 这类范围能通过校验却永远匹配不到文件，现在
会被拒绝；目录范围请写 `src/**`。这是本版本唯一的校验收紧；atlas 标题、中文地图
文案、补全与 config 输出的修复无需迁移。

### 0.29.0 之后

校验收紧：已实施与归档决策的 `Consequences` 必须有实际正文，提案还须填写 `Acceptance criteria` 和 `Risks`。空标题、HTML 注释和围栏示例均不满足这些要求。运行 `adrkit validate --all`，由作者补齐缺失的实质内容；这不是机械迁移，不能靠占位文字通过校验。修改归档须在提交中说明原因。否决提案仍只要求问题、方案、备选和否决理由，无需补完已经放弃的实施计划。

### 常设指令的代际标记

`AGENTS.md` 中的常设指令段落归你所有：可选的代际标记 `<!-- adrkit: standing-orders <id> -->` 表示已与哪一代模板核对，不保证正文完全一致。允许翻译、缩写和本地修改；项目专属要求放在该段之外。旧标记会让 `init`、`update`、`list`、`instructions` 和 `relevant` 给出提示：先与当前 `adrkit-init` 模板比较、处理变化，再更新标记。无标记的段落保持安静，包括旧安装；核对后保留或添加当前标记，即可选择接收以后的模板变化提醒。缺少整段规则时，init/update 仍会给出独立提醒。

### 可视化收敛（ADR 33、ADR 36）

`adrkit atlas` 是唯一的可视化命令：`adrkit atlas` 输出完整档案，`--map` 选择决策地图，`--record <N>` 渲染单条决策的商议树。树默认输出 HTML，也支持 `--format html`；`--diagram` 已移除，`adrkit graph` 与 `adrkit tree` 已删除，`atlas` 的多余位置参数会报错，所有格式的地图导出都必须显式添加 `--map`。

### 包名、命令与运行时

npm 包名是 `adr-kit`，CLI 命令是 `adrkit`（npm 上没有 `adrkit` 包）。CLI 需要 Node.js 22.22 或更新版本；更早的 Node.js 版本不再受支持。

### CLI 严格化（0.27.0）

所有命令现在拒绝多余位置参数而不是忽略；`record`、`propose` 和 `note` 例外，它们把未加引号的 shell 词拼接为一个标题或文本。`validate` 只接受记录名或 `--all` 之一，不能同时给出。

### 归档清单（0.23.0 及更早）

0.23.0 及更早版本写下的 `adr/archived/MANIFEST.json` 已不再读取，直接删除即可。
