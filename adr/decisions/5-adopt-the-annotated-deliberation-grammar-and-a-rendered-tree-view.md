# ADR: 5 adopt the annotated deliberation grammar and a rendered tree view

## Problem

ADR 3 made a grilling session's design tree a `## Deliberation` appendix of
nested bullets — `- <text> [status]` — and rendered it with `adrkit tree`.
Rendering the first real tree exposed the schema's thinness. The renderer
matched `[status]` only at end of line, so a node carrying a reason after the
tag (`... [rejected] - why`) was silently left unclassified; the graph could
not tell a question from an accepted option, because both are just
`[settled]` bullets; and nothing recorded the agent's recommendation, so the
signal the appendix exists to preserve — whether the human took the
recommendation or overrode it — was absent. The visualization is the probe that
made each gap visible: a view that cannot be drawn is a data model that is not
finished.

## Decision

- **Extend the `## Deliberation` grammar.** A node is
  `- [Q: | A: ]<text>[ [status]][ (recommended)][ — <reason>]`:
  - `Q:` / `A:` marks a question or an option (optional; otherwise inferred:
    a node with children is a question, a leaf is an option, the top level is
    the root);
  - `[settled]`, `[rejected]`, `[open]` is the node's state;
  - `(recommended)` marks the option the agent recommended;
  - ` — <reason>` explains a node, typically a rejected option.
  A question's answer is its `[settled]` child; a settled child without
  `(recommended)` means the human overrode the agent, and the view marks it.
- **Render by type and state, not just state.** `adrkit tree` gives the root,
  questions, and options distinct shapes, colors them settled/rejected/open,
  marks the recommended option, and marks an overridden question.
- **Add `adrkit tree <N> --html`**, emitting one self-contained HTML file that
  renders the tree in a browser (Mermaid from a CDN), so the picture is a
  one-command artifact rather than text to paste.
- **Migrate ADR 3's tree and use it as the acceptance sample**, because it is
  the tree that exposed the gaps.

## Alternatives considered

- **A fenced YAML tree instead of the annotated outline**: rejected. It is
  fully structured but much less readable and diffable in the raw record, and
  the outline with a fixed grammar carries the same fields.
- **Keep `- text [status]` and only fix the end-of-line bug**: rejected. It
  would color the graph correctly but still could not show questions versus
  options or the override signal, which is the reason to render at all.
- **Client-side SVG generated by the CLI (no CDN)**: deferred. It would remove
  the CDN dependency from the generated file but needs a layout engine; Mermaid
  gives the first usable picture now, and the data model is the point.
- **Treat the visualization as presentation and not invest**: rejected once the
  need was framed as a data-model probe; a view that cannot be drawn is
  feedback about the schema, not decoration.

## Consequences

- The `## Deliberation` grammar changes, so `src/core/deliberation.ts`, the
  `adrkit tree` renderer, the `deliberation-tree` spec,
  `docs/record-format.md` (English and Chinese), the `adrkit-grill` skill and
  its mirror, and tests move together; ADR 3's tree is migrated.
- Richer nodes cost a little more context, but the appendix is already exempt
  from the mandatory full read.
- The override marker makes the `decided-by` declaration reviewable after the
  fact: a reader can see whether the human's answers diverged from the agent's
  recommendations.
- `adrkit tree --html` introduces a viewing dependency on a Mermaid CDN; the
  CLI itself stays dependency-free.
