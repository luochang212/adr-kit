# ADR: 34 publish the decision atlas in both site languages

## Problem

ADR 29 published the site's decision atlas in Chinese only: a showcase of
this repository's own records, "not a localized site page", linked as-is
from both homepage languages without a bilingual promise. The atlas renderer
has since gained an English chrome, and an English page had been generated
by hand into `site/public/decisions/en.html` — linked from nowhere and
regenerated by no build, so it went stale the day the records moved.

## Decision

- The site build renders the atlas twice from the same records: `index.html`
  in Chinese and `en.html` in English. Each footer links its sibling
  (`English` / `中文`) beside the commit pin, through a `langHref` option on
  `renderDecisionAtlas`.
- One template and the translation table remain the only carriers; nothing
  is hand-localized, so the `ui.ts` copy rule stays inapplicable. This
  amends ADR 29's Chinese-only showcase trade-off; its build-time
  generation, slot contract, and commit pinning are unchanged.

## Alternatives considered

- **Delete `en.html` and stay Chinese-only**: rejected by the maintainer.
  The English chrome exists for non-Chinese readers, and the published page
  is where they meet it; an unlinked manual artifact was the worst of both.
- **Hand-maintained bilingual pages**: rejected. Two files carrying one page
  is exactly the drift the translation table exists to prevent.

## Consequences

### Verification

- `tools/build-decision-atlas.mjs` writes both pages and the footer links
  are asserted in both directions by `test/decision-atlas.test.ts`, which
  also covers the link's absence without `langHref`.
- `npm test`, `npm run typecheck`, `npm run build`, `adrkit validate --all`,
  and the site build pass.

### Trade-offs

- Two generated artifacts ship per build; both come from one template, so
  the cost is a second file, not a second source.
- The English chrome is a machine translation of fixed strings; record
  bodies stay in the language they were written in, and a page mixing
  languages is possible when a Chinese-only repository is rendered in
  English — accepted, since the chrome is what the tool owns.

## Later changes

**Amended by ADR 37:** both pages remain generated from one template, but their
footers now retain only short generator attribution and the pinned commit.
Home and sibling-language links and their renderer options are removed to
reduce mobile wrapping. The bilingual build remains active; the earlier
footer-link verification describes the behavior before ADR 37.
