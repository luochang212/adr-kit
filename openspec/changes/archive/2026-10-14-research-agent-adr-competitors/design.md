# Design

## Context

See proposal.md - Why. 研究基线为本仓库 `f76872965115e628888394f78d6e649ca725477c`（0.17.0），分享链接已读取页面内嵌会话文本。旧研究仅作 2026-09-21 的历史观察，不作为当前产品约束；ADR 18/19/20/21/22 与当前代码优先。

## Goals / Non-Goals

**Goals:** 将捕获、方案形成、检索、约束执行、浏览管理分开比较；逐项解释可以借什么、为何借、成本和如何证伪。对名字相似的 `luochang212/adr-kit` 与 `mbeacom/adrkit` 明确消歧。

**Non-Goals:** 本研究不决定引入 MCP、hook、可执行规则、多格式或 LLM 服务；不修改 ADR 格式及生命周期，不安装竞品到工作仓库，不声称完成同模型效果排名。

## Decisions

这些是本次研究的交付方法，不是长期产品架构决定。

- 使用本地 spec-driven schema，文档研究 `skip_specs: true`；避免给没有行为变更的研究制造规格。
- 以官方仓库、固定 commit 的源码与测试为能力依据，网页搜索作为发现入口；分享内容只是待核验线索。优于仅复述 README 或按 stars 排名。
- 并行只读核验两组竞品，由主 agent 单独写仓库工件。记录核验级别，不将存在测试等同于本机已运行。
- 输出一个中文 Markdown 主报告及 PDF 阅读版，英文与中文目录都明确报告语言；避免两份手工维护的研究结论。
- 维护候选清单而非采纳清单；每项标记已有、建议小实验或暂缓，并指定复核门槛。研究可完成，路线仍开放。

## Risks / Trade-offs

- [README 与源代码不一致] → 优先固定 commit 的实现；保留宣称与观察差异。
- [把路径命中当作完整上下文或代码合规] → 检查 lifecycle、无 scope 记录、空结果、diff 新旧路径；明确可检索和可执行不同。
- [旧研究固化过时结论] → 新报告明示 ADR 21/22 已改变旧研究的前提，保留旧稿的历史时间范围。
- [功能扩张压过本产品价值] → 候选逐项估计依赖、维护面、平台绑定和真实收益，不自动创建实现 proposal 或 ADR。
- [源码阅读无法验证模型效果] → 不给生成质量、召回率、用户满意度编造数字；提供独立后续实验。

## Migration Plan

只添加文档与目录链接；撤回可删除本次新增研究工件并移除目录行。PDF 为阅读副本，Markdown 为可审查文本。研究变更保持 active，是否 archive 留给后续请求。
